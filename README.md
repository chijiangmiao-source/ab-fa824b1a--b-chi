# Büchi 自动机语言包含性复核台

在页面填写共同 ASCII 字母表、两台各至多 8 个状态的 Büchi 自动机（初态、
接受态、按字母迁移），提交复核后判定 **L(左) ⊆ L(右)**。

- 右侧为确定 Büchi 自动机：每个状态 × 字母**恰好一条**迁移；
  缺失、悬空、重复引用会一次性全部列出，并清除上一次结论。
- 不包含时给出可逐字符重放的反例：`前缀 + (环)^ω`，并展示左右两侧
  对应的前缀状态链与环状态链（环上含左侧接受态、绝无右侧接受态）。
- 包含时仅返回包含结论，绝不生成伪造反例。
- 左侧允许非确定分支，仅经非确定分支进入接受环也能正确判定。

## 算法

在乘积图 `(左侧状态, 右侧状态)` 上搜索“左侧接受态无穷出现、右侧接受态
仅有限出现”的路径（即 L(左)\\L(右) 非空的证据）：

1. **阶段 A（前缀）**：从乘积初态做可达性搜索，所有节点与出边
   `(字母, 左后继, 右后继)` 按稳定顺序枚举；先处理右侧仍可经过接受态的
   前缀部分，再处理其余部分。
2. **阶段 B（环）**：在右侧全为非接受态的闭子图中，对可达节点求 Tarjan
   SCC，选取可闭合（单点需有子图内自环）且含左侧接受态的分量，
   在分量内构造确定性最短环。

这是完整的乘积图搜索，不以有限抽样或单一路径代替。测试中另有 400 组
随机自动机与独立 Kosaraju 参照实现的差分对拍。

图搜索在后台单工作线程执行；任务按 id 隔离结果，排队中被新提交超越的
任务直接作废，过期计算不会覆盖当前结果（前端亦按提交代号丢弃过期响应）。

## 本地运行（无需第三方依赖，Python 3.11+）

```bash
python -m app.server            # 默认 0.0.0.0:8080
PORT=9090 python -m app.server  # 自定义端口
# 健康地址
curl http://127.0.0.1:8080/health   # -> {"status":"ok"}
```

## Compose

```bash
docker compose up -d --build           # 宿主机端口默认 8080
HOST_PORT=9090 docker compose up -d    # 自定义宿主机端口
curl http://127.0.0.1:${HOST_PORT:-8080}/health
```

### 验收（verify 服务）

verify 服务依次执行：代码测试（包含 / 反例 / 非确定分支 / 输入校验
边界）→ 构建检查（字节码编译）→ 请求健康地址做 HTTP 冒烟，结束即退出，
以退出码报告验收结果：

```bash
docker compose run --rm verify
echo $?    # 0 表示验收通过
```
